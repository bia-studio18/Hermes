# Schemas

Hermes defines canonical schemas for different data domains. Each schema specifies field names, types, constraints, and primary keys — providing a contract that data must satisfy.

## Built-in Schemas

### `economic.observation`

Canonical economic indicator observation:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `entity_id` | `str` | Yes | Country or entity identifier |
| `date` | `datetime` | Yes | Observation date |
| `indicator` | `str` | Yes | Indicator code (e.g., "NY.GDP.MKTP.KD.ZG") |
| `value` | `float` | No | Indicator value |
| `unit` | `str` | No | Unit of measurement |
| `frequency` | `str` | No | Data frequency (e.g., "Y", "M", "Q") |
| `source` | `str` | No | Data source |

Primary keys: `entity_id`, `date`, `indicator`

## Schema Base Classes

### `Schema`

```python
from hermes.schemas import Schema, FieldDef

schema = Schema(
    name="my_schema",
    version="1.0.0",
    fields=[
        FieldDef(name="id", dtype="str", required=True),
        FieldDef(name="value", dtype="float", nullable=True),
    ],
    primary_keys=["id"],
    description="My custom schema",
)
```

### `FieldDef`

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `name` | `str` | *(required)* | Field name |
| `dtype` | `str` | *(required)* | Data type |
| `nullable` | `bool` | `True` | Whether null values are allowed |
| `required` | `bool` | `False` | Whether the field is required |
| `description` | `str \| None` | `None` | Human-readable description |
| `unit` | `str \| None` | `None` | Unit of measurement |
| `constraints` | `dict` | `{}` | Additional constraints |
