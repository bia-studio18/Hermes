Data Acquisition

How Hermes fetches data from external sources and manages raw caches.

Overview

Data acquisition is the first stage in the Hermes pipeline. It handles fetching raw data from connectors (APIs, files, feeds) and caching it locally with a time-to-live (TTL) so repeated requests don't hit the network unnecessarily.

RawCache

The RawCache (hermes/acquisition/cache.py) stores raw API responses on disk. It implements a get-or-fetch pattern:

  • If a cached response exists and hasn't expired (based on TTL), return it.
  • Otherwise, fetch from the connector, store the response, and return it.

This is the foundation of reproducible pipelines — the same input data can be reprocessed without re-fetching.

Scheduler

The scheduler (hermes/core/scheduler.py) supports cron expressions and interval-based scheduling for recurring data fetches. Use the @schedule decorator and module-level functions:

from hermes.core.scheduler import schedule, start, list_jobs

@schedule(time="0 0 * * *")
async def fetch_gdp():
    ...

start()      # Run the scheduler loop
list_jobs()  # List registered jobs

Top-Level API

The acquisition layer provides four top-level functions:

  • hr.fetch(source, **kwargs) — Fetch data from a registered connector (cached)
  • hr.fetch_raw(source, **kwargs) — Fetch raw data bypassing the cache layer
  • hr.ingest(source, **kwargs) — Fetch and return data packaged with metadata
  • hr.read(path, **kwargs) — Read a local file (csv/parquet/json/jsonl) into a DataFrame
  • hr.sync(source, **kwargs) — Incremental synchronization with state persistence

Error Handling

Acquisition errors are wrapped in AcquisitionError (from hermes/core/errors.py), which extends the base HermesError. The error hierarchy ensures that acquisition failures are distinguishable from parse, validation, or storage errors.
