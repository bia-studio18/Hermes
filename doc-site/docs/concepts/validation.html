Validation

Checking data against schemas, contracts, and custom rules.

Overview

Validation ensures data meets expected quality and structural requirements before it enters your pipeline. Hermes provides a flexible validation framework with built-in checks and a ValidationReport that captures all findings.

Components

  • validate() function — The entry point for running validation checks.
  • NotNull check — Verifies that a column has no null values.
  • ValidationReport — Structured output with pass/fail status, errors, and warnings.
  • DataContract — A declarative way to specify validation rules (schema + constraints).

ValidationReport

Every validation run produces a ValidationReport that contains:

  • status — Pass or fail.
  • errors — List of validation errors.
  • warnings — List of non-fatal warnings.

Data Contracts

A DataContract (hermes/validation/) is a declarative specification of what your data should look like: which columns must exist, their types, whether they can be null, and any value constraints.

Current Status

The validation framework (validate, NotNull, ValidationReport, DataContract) is implemented. The top-level convenience function is not yet wired up:

  • hr.validate() — Planned

Error Handling

Validation errors are wrapped in ValidationError (from hermes/core/errors.py).
