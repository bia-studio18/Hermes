Guidelines

Coding standards and conventions for Hermes contributors.

Code Style

  • Follow PEP 8 (enforced by ruff).
  • Use type hints for all public functions.
  • Keep functions focused and short.
  • Use descriptive variable names.

Imports

Organize imports in this order:

  1. Standard library
  2. Third-party (polars, pyarrow, pandas, duckdb)
  3. Internal (hermes)

Error Handling

Use the Hermes error hierarchy. Raise specific error types, not generic exceptions:

from hermes.core.errors import AcquisitionError, ParseError

# Good
raise AcquisitionError("Failed to fetch data from FRED API")

# Bad
raise Exception("Something went wrong")

Documentation

  • Write docstrings for all public functions and classes.
  • Use Google-style docstrings.
  • Include type information in docstrings.

Testing

  • Write tests for all new functionality.
  • Keep tests isolated and deterministic.
  • Use descriptive test names.
