Architecture Overview

How Hermes is structured and how data flows through the system.

Overview

Hermes is organized as a modular Python package where each pipeline stage is a separate module. The central abstraction is the Dataset, which bundles data with its metadata, provenance, and lineage.

Pipeline Stages

Data flows through Hermes in a linear pipeline:

  1. Acquisition — Fetch raw data from external sources (connectors) or local files.
  2. Parsing — Convert raw data into typed Polars DataFrames.
  3. Normalization — Clean and transform data into consistent formats.
  4. Validation — Check data against schemas and custom rules.
  5. Profiling — Generate statistical summaries and quality scores.
  6. Storage — Persist datasets to disk or databases.
  7. Querying — Filter, aggregate, and join data.

Design Principles

  • Local first — No cloud dependencies. Everything runs on your machine.
  • Interoperable — Built on Polars, Pandas, PyArrow, DuckDB.
  • One auditable object — The Dataset carries the complete story.
  • Honest by default — Implemented features are documented as implemented.
